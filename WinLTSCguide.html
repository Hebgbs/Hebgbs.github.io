Installation

No matter how you go about this process, you will need to obtain an installation binary from Massgrave, through their MAS portal. Once you've obtained that, then the advice below becomes significant.

Fresh instance

You'll need a functional computer for this. There are a few ways this can be handled, two most practical I will illuminate:

  • Rufus
    • Made specifically for Windows
    • Allows bypass of privacy questions / OOBE content
    • Permits local account creation as part of its answer file
    • Enables Windows To Go functionality for opertion via USB-attached DRAM media

    There are other features Rufus provides, but none of these are important now. What matters is that you are afforded the possibility of extracting a disc image onto a USB device, so it is bootable and useful as an installation media for Microsoft Windows.

  • Ventoy
    • Made to be cross-platform (except for Apple OSes)
    • Enables booting into not only Windows, but other open-source system images, purpose-made utilities and virtual device snapshots as-well
    • Can function with Secure Boot for open-source distributions which function with Secure Boot, as-if it were "Flashed" through other methods
    • Allow the device to continue being writable.

    With Ventoy, specifically, there are select caveats which make it more difficult to initialise, but for some its foibles may be outweighed by the boons it can provide. There are a couple of considerations to ponder before writing Ventoy onto a target USB-attached media:

    1. Partition style — By default, this will be set to MBR. Great for older machines, but newer machines may use GPT for modern boot instead. The easy way of figuring this out is to open diskmgmt.msc and context-click on the disk bearing the partition which contains Windows. View Properties, and select the Volume tab. This information is held there; match it in ventoy2disk.exe.
    2. Secure Boot — You should just leave this on. Don't question it; unless you keep the MBR partition style, you'll end up using Secure Boot, and this feature provides a .crt file in its own VTOYEFI partition, which is what you'll need to find when prompted for validity in your baseboard firmware's MOK management.

    Once you're finished writing the contents of Ventoy to the USB device, the Enterprise LTSC .iso can be put into the partition labelled Ventoy. When this operation is finished, you can then use Ventoy to initialise installation.

    Not all machines, devices and boot media may like Ventoy as a boot method. On select machines, Windows' installation may be prohibited due to alleged "Missing" drivers. If you encounter problems despite best efforts, fall back to conventional boot media creation processes.

No matter the method, and no matter the Windows release, you'll skip inputting a product key during intallation anyway — this will be resolved later.

Upgrade process

There are several things you need to do as an end-user so you can adequately "Upgrade" Windows by effectively installing an older copy of it:

  1. Change edition in registry
  2. Select edition during setup
  3. Declare whether or not you want to keep installed applications

Let's run through these things in order

Changing edition

This is very simple to do; in the registry, you can change a setting called EditionID. Within regedit.exe:

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion

Then, find EditionID and change it to one of either the following:

  • EnterpriseS
  • IoTEnterpriseS

Later on, when activating Enterprise LTSC with Microsoft Activation Scripts, you'll end up with the IoT Enterprise LTSC license anyway, so personally I would go with EnterpriseS as the edition. So, here's what else you could do in an elevated command prompt so you can set EditionID to my preference:

reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion" /v EditionID /d EnterpriseS /f

Once that is set, you can now launch the setup binary for Windows 11 Enterprise LTSC. This will reset upon setup exit, so spare yourself from time by doing this right once. If corcumstances makes this not possible, you must re-define the edition to use.

Selecting edition

Selecting the edition to use is fairly simple, but depends on the edition you've defined. as follows:

  • EnterpriseS — Enterprise LTSC
  • IoTEnterpriseS — IoT Enterprise LTSC

Mind the version to use, and you shouldn't be prompted for a license key when proceeding to install Enterprise LTSC in Windows.

Keeping apps and files

After selecting the edition dpeendent on EditionID in the registry, you will be prompted for what to keep. You can elect to keep apps and files if you like, but my personal preference i to omit apps, because for much commercial applicatins, you likely have a key or activation method which interacts with th registry already, and even if you do keep apps and files, the registry also becomes completely replaced.

If you already know where software activation indicators are in your registry, and if your software doesn't react poorly to the instance change after re-upgrading, then feel free to back those keys up prior to initiating the process. Else, just ignore it and deal with the problem(s) where they occur.

Either way, whether starting from nothing or "Upgrading" to Enterprise LTSC, you'll want, and need, to do some things which ensure your privacy by minimising how often your instance uses the Internet for contacting Microsoft. The following sections will help you deal with post-installation tasks, when prompted for your account, and after you've reached the desktop. Above all else, do not be connected to the Internet during initial steps, untill you are prompted to be online. If your Internet comes from a gateway / modem attachment, physically disconnect it from the machine until necessary.

Obtaining software

You may begin to seek out and receive updates for Windows from hereon. But before you do that, you should establish Microsoft Store and handle some other things prior to removing Microsoft's applications. You may be tempted to use what's already available to do this, but if you want to ensure your privacy while using a Microsoft OS where telemetry is disabled, and CoPilot doesn't exist, using Microsoft's web browsers would be anti-thetical to this end-goal.

To obtain and make functional the Microsoft Store, open Powershell and send wsreset -i; after some time, this will install and make usable the Store application. To obtain winget, which at present instance state isn't installed, you can use Store to search for UniGetUI and proceed to obtain it, but then decline to install after it adds in other dependencies for it to work, one most notable being the winget application. This will help you to easily resolve the other problem Enterprise LTSC users typically have; applications requesting for an app providing ms-gamingoverlay.

Exit Powershell, open it again and type in the following to test if all of this has enabled winget:

winget list

You will be prompted for agreement with Microssoft's terms of use the first time you run winget; choose Yes. After you've seen it perform, run also the following:

winget install 9NZKPTSNW4P

This action will use winget to install Microsoft's Game Bar, which is the mythical application you just can't find in Store by itself no matter how hard you seek. Once finished, you can use winget in Powershell or the Microsoft Store to obtain much else.

Microsoft Store only works with applications which have a store ID. For binaries unlisted in the store, using winget with the search argument and query after will enable you to find other applications provided as routines to initialise retrieval from a domain and execution of an installation binary for a more traditional software management experience. Pair your learning from installing Game Bar by store ID with searching for popular utilities you may be interested in. An example using Steam:
winget search steam

For those upgrading from (GAC) "Core" to LTSC

If you've elected to upgrade your existing instance of Windows and declined to keep apps, that doesn't mean your apps are gone per-se, but it does mean you will need to re-install everything. My prior recommendation to omit apps wasn't just out of an abundance of fear that things like OneDrive and CoPilot would carry over into the new instance should you had not wanted those, but also because a lot of problems people have with Windows is application and autostart bloat, which is easier to manage starting from nothing, than to retrofit and tool around with an existing installation.

Since the apps are still there, preferences for them are also present; in %systemdrive%\Windows.old, all of the old application data too exists. So, for anything that should be at %appdata% or %localappdata%, it will instead be at the place it goes to, with Windows.old in the directory path. Let's use Mozilla Firefox installed traditionally as an example;

To install Firefox as not a store app via winget:
winget install mozilla.firefox

Presented are two directories, both which hold configurations and preferences for Mozilla Firefox:

  • Default, normally accessed via %localappddata%
    • %systemdrive%\Users\%username%\AppData\Local\Mozilla
  • Moved, after the upgrade process
    • %systemdrive%\Windows.old\Users\%username%\AppData\Local\Mozilla

The highlighted portion shown is where your old stuff would be. If you're inclined on copying it, then in cmd as administrator you can do this:

copy %systemdrive%\Windows.old\Users\%username%\AppData\Local\Mozilla %localappdata%

Other applications will vary, but the general ideas still apply; if you know where it was, then now you know where it is.

Manually removing Edge residuals

Even if you remove Edge, there are files which may still exist, related to Edge and (where applicable) WebView2 which may still be in your system. There are three things of interest you may want to check, all to ensure no errant processes attempt to continue collecting data without your consent, to ensure operations tangential to the browser are disallowed from occurring, and dormant non-functioning components are removed;

  • Scheduled tasks
  • Services
  • Group policies

If you want to completely remove Edge, we need to get rid of these, wherever they may occur. So, should removing WebView2 in Windows 11 not be an option, if you are in Windows 10, or if Microsoft changes their mind on what you can do to get rid of everything Edge coordinates with, then you can follow these steps to eventually get rid of these things.

Bear in mind, not all procedures shown below may be necessary. Spend some time to check for these things before following these instructions; if they don't exist, you don't have to do it.

Services

To remove the services for Edge Update, there are two which may concern you in windows 10. First check if they are there by browsing installed applications. Ig you see anythingg related to Edge update there, then as administrator open cmd.exe and perform the following:

sc delete edgeupdate
sc delete edgeupdatem
Once those thing are rid-of, they should no longer be there io invoke cheduled updates for Edge and related software.

Tasks

Simply go into task scheduler and remove the tasks related to Microsoft Edge. Scroll through them and delete all you can find.

Group policy objects

Now we get to the fun part. So, based on some advice I found on Reddit, there's a way to force yourself into te privileged user which is allowed to modify specific system components.

Fun fact: Administrator is not the most privileged class in any Windows instance!

To worm yourself into the position of TrustedInstaller, first you need to produce two shortcuts; One to adjust script execution policy and install NuGet which will enable the use of other scripting, the other to elevate oneself in the position of nt system/trustedinstaller (as-impersonated by nt authority/system:

  1. To enable becoming TrustedInstaller
    C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -c "Set-ExecutionPolicy Unrestricted CurrentUser;Set-ExecutionPolicy Unrestricted LocalMachine;install-module ntobjectmanager -Force"
  2. To execute Powershell as TrustedInstaller
    C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe "Import-Module ntobjectmanager;sc.exe start trustedinstaller;$p=Get-NtProcess TrustedInstaller.exe;New-Win32Process powershell.exe -CreationFlags NewConsole -ParentProcess $p"

Both of these must be executed as administrator, in the order as they are shown.

These are necessary things to do for deleting the group policy objects without having to use an alternative system intance for seleting files in spaces you are normally disallowed even as Administrator to remove.

After asending yourself to demi-god status for your Windows instance, we can now eliminate the group policy objects through this elevated Powershell instance as-shown:

remove-item $env:windir\PolicyDefinitions\MicrosoftEdge.admx
get-childitem -path $env:windir\PolicyDefinitions\*\MicrosoftEdge.adml | remove-item
You could just delete the locale-specific .adml files, but the catch-all using get-childitem is just-as effective.

Activation

Finally, when everything is exactly how you want, we can wrap up procedures with activation.

To activate Windows, do the following in powershell:
irm https://get.activated.win | iex

When this command is sent, it will obtain the script which will prompt a menu in Command Prompt to appear. Select option HWID and wait ffor the magic to happen.
